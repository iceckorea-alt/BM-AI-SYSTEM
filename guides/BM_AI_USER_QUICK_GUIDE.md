# BM AI 사용자 퀵가이드 — 직원용

안내서 v3.0 · 2026-10-21 · 규정 원본이 아니다. 충돌하면 GitHub `governance/BM_CORE.md`가 우선이다.

## 1. 시작
AI에게 `비엠접속`(Claude는 `/비엠업무`)이라고 하면 AI가 `BM_STARTER → BM_CORE → 프로젝트 목록 → 해당 READ` 순서로 스스로 확인한다. 파일 위치를 외울 필요 없다. 프로젝트명과 할 일을 말하면 된다.

## 2. 자주 쓰는 말
- 열기: `홍대 캔버스 프로젝트 열어줘`, `이 프로젝트 다음 할 일 알려줘`
- 작업: `이 자료 기준으로 공문 작성해줘`, `현재 진행상황 정리해줘`, `결과물 저장 위치 알려줘`
- 확인: `모르는 건 물어봐`, `추측하지 말고 확인된 것만 써`
- 다시 기준 잡기: `BM_STARTER 다시 확인해`, `READ 최신본 다시 읽어`

## 3. 저장은 자동
확정된 결정·완료한 일·상태 변화는 AI가 바로 READ에 저장하고 다시 읽어 확인한다. 직접 저장시키고 싶으면 `작업 결과 저장`(또는 `현재 상태 저장`, `READ 업데이트`)이라고 하면 된다.
아이디어·초안·AI 추천은 확정으로 저장되지 않는다. 확정하려면 분명히 말해준다: `이걸로 확정`.

## 4. 누가 했는지 남는다
READ에는 작성자 코드가 붙는다. 예) `J`=대표 직접, `J·CL`=대표 지시로 Claude가 기록, `J·GPT`=대표 지시로 ChatGPT가 기록.
결정에는 등급이 붙는다: `[대표결정]` `[책임자결정]` `[제안]`. 예산·계약·대외공문·일정·장소는 대표 결정이 있어야 확정이다.

## 5. 마감
`마감`이라고 해도 바로 종료되지 않는다.
`결과보고서 작성 → READ 정리 → 마감요청 → Docswave 결재 → 승인 후 종료`
확인되지 않은 인원·예산·성과는 AI가 추정하지 않고 묻는다.

## 6. 직접 바꾸지 않는 것
프로젝트 등록·종료·삭제, 대량 파일 이동, 공유범위·관리자권한, 비밀번호·토큰·OTP. 필요하면 AI가 요청 절차를 밟는다.

## 7. 완료보고에서 볼 것
`READ 저장·확인 완료` / `READ 변경 없음` / `READ 저장 미완료 — 사유` 중 하나가 표시된다. 결과물 파일 저장 여부도 따로 확인한다.

## 8. 도움말
`매뉴얼`·`퀵가이드`·`사용법`·`도움말` → 이 안내. `전체 가이드` → 전체 내용과 링크.

**한 줄 사용법: 프로젝트명을 말하고 일을 시킨다 → 확정은 `확정`이라고 말한다 → 끝낼 때 `마감` → 모르면 `매뉴얼`**
