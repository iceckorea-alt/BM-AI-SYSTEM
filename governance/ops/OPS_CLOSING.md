# OPS_CLOSING — 마감·결과보고·종료

규정 v3.1 · 2026-10-21 · `마감`, `프로젝트 마감`, `마감요청` 지시를 받았을 때만 읽는다. 결과보고서 서식은 `templates/PROJECT_RESULT_REPORT_TEMPLATE.md`.

## 1. 상태
`기획 / 진행 / 보류 / 마감요청 / 취소 / 종료`
- `마감요청`: 업무는 끝났고 결과보고·정산·결재 등 종료 전 확인이 남은 상태
- `종료`: 대표(또는 지정 승인권자)의 마감 결재까지 확인되어 공식적으로 닫힌 상태
- `마감`은 즉시 종료가 아니라 마감 절차를 시작하라는 뜻이다.

## 2. 절차
1. INDEX → 최신 READ → 핵심 원본 → 최종 산출물 → 기존 결과보고 존재 여부를 확인한다.
2. 결과보고서가 없으면 템플릿 기준으로 확인된 사실만으로 초안을 만든다. 당초 계획 대비 변경사항은 프로젝트 LOG에서 뽑는다. 있으면 템플릿·외부기관 요구 기준으로 누락을 점검한다.
3. 빠진 필수정보(실제 수행내용·변경사항, 참여·실적 수치, 성과, 예산·정산, 문제점, 후속조치)는 한 번에 묶어 묻는다. 답을 받기 전 추정해 완성하지 않는다.
4. 외부기관이 HWP/HWPX/PDF나 지정서식을 요구하면 그 기준이 우선이다. 아니면 DOCX로 만든다(문서 제작 기능이 없으면 초안만 주고 `DOCX 생성 미완료`로 안내).
5. 프로젝트 `05_성과·결과`에 `YYYYMMDD_결과보고서_프로젝트명.docx`로 저장한다(폴더가 없으면 생성). Google Docs 변환본을 DOCX 저장 완료로 보고하지 않는다. 파일 존재·형식·링크를 확인한다.
6. READ `결과보고` 링크를 연결하고 완료·미결·정산·후속조치·최종 산출물을 정리한 뒤 상태를 `마감요청`으로 바꾼다. INDEX도 맞춘다(권한 없으면 업데이트요청).
7. Docswave 마감 결재를 상신한다. 직접 연동이 없으면 상신 준비자료를 주고 `마감요청 준비 완료 / Docswave 상신 미완료`로 안내한다. 결재 감지 기능이 있는 것처럼 말하지 않는다.
8. 결재 승인이 확인된 뒤에만 시스템관리가 INDEX·READ를 `종료`로 맞춘다. 종료를 이유로 정산·계약까지 완료 처리하지 않는다.
9. 최종 산출물·결과보고·결재·정산·공문 링크를 재확인한다. 중복·임시파일 정리와 아카이브는 후보만 제시하고 승인 없이 삭제하지 않는다.

## 3. 결과보고서 필수 내용 (대외 프로젝트)
사업개요 / 당초 계획·목표 / 실제 추진내용·세부 실적 / 참여인원·일시·장소 / 정량·정성 성과 / 계획 대비 변경사항과 근거 / 예산·정산(해당 시) / 문제점·개선 / 후속조치·활용 / 최종 산출물·증빙 목록과 링크

## 4. 간이 결과요약
소규모 내부 프로젝트는 대표가 허용하면 간이 결과요약으로 대체할 수 있다. 대외 제출·보조금·위탁·행사·교육 등 증빙이 필요한 프로젝트는 임의로 간소화하지 않는다.
