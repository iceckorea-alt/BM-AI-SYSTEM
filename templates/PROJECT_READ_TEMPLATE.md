# PROJECT_READ_TEMPLATE

READ Schema v2.0 · 2026-10-21 · READ를 새로 만들거나 구조를 바꿀 때만 읽는다. 실제 READ는 각 Drive 프로젝트 폴더의 Google Docs `YYYY_프로젝트명_READ`.

## 작성 규칙
- 아래 `---` 사이가 READ 본문이다. 이 작성 규칙은 READ에 복사하지 않는다.
- 0장은 항상 최신으로 유지한다. AI는 평소 0장만 읽고 필요할 때만 아래를 읽는다.
- 같은 사실은 한 곳에만 쓴다. 결정은 4장, 할 일은 3장, 현장·운영 정보는 2장.
- 해당 없는 섹션·항목은 만들지 않는다. 빈 `미연결` 줄을 나열하지 않고 6장 끝 `미연결:` 한 줄에 모은다.
- 확인되지 않은 값은 `미확정`. 추정하지 않는다.
- 3장 할 일 상태 태그: `[진행]` `[대기]` `[할 일]` `[승인 필요]`. 끝난 일은 3장에서 지우고 7장 이력(필요하면 4장)에 남긴다.
- 4장 결정은 최신이 위. 등급 `[대표결정]` `[책임자결정]` `[제안]`과 결정 주체를 붙인다. v2.0 전환 때 옮긴 과거 결정 중 결정 주체가 기록되지 않은 것은 `[이관]`으로 표시하고, 대표가 확인하면 `[대표결정]`으로 바꾼다.
- 7장 이력은 최근 10건. 같은 날 같은 작성자 건은 한 줄로 합친다. 넘치면 오래된 것을 8장 보관으로 옮긴다.
- 작성자 코드: 사람 `J`, AI가 쓰면 `J·CL`, `J·GPT`. (`BM_CORE` 4장)
- 프로젝트 고유 상세(큐시트·출연진·장비표 등)는 9장 부록에 두거나 별도 문서로 만들고 링크한다.
- 대외 프로젝트는 `마감요청` 전 실제 결과보고서 파일 링크를 6장에 연결한다(`ops/OPS_CLOSING.md`).
