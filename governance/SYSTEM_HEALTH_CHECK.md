# SYSTEM_HEALTH_CHECK — 정기 점검표

규정 v3.12 · 2026-11-07 · 점검할 때만 읽는다. 규칙 설명은 하지 않고 확인 항목만 둔다. 보고는 `확인 완료 / 수정 완료 / 미검증 / 사용자 결정 필요`로 구분한다. 권한 때문에 확인 못 한 항목은 `미검증`.

**점검 시작 절차:** `BM_STARTER`에서 현재 규정 버전을 확인하고, `CHANGELOG.md`의 해당 최신 버전 항목만 먼저 읽어 변경 범위를 파악한 뒤 `BM_CORE`와 본 점검표를 확인한다. 그 버전에서 바뀐 사항이 실제 Drive·Sheets·Airtable·플러그인에 반영됐는지를 먼저 집중 점검한다. 과거 CHANGELOG 전체와 `archive/MIGRATION_*`은 변경 경위가 필요할 때만 읽는다.

## 1. 구조·입구
- [ ] Drive 루트에 `BM_STARTER`, `BM_PROJECT_INDEX`, 00_BM공통, 01_BM서울, 02_BM인천, 98_아카이브, 99_시스템백업만 있다
- [ ] STARTER가 BM_CORE raw 주소와 현재 규정 버전을 안내한다
- [ ] README·BM_CORE·STARTER·CHANGELOG의 현재 시스템 버전이 일치한다. 개별 문서의 마지막 개정 버전·Schema·플러그인 배포 버전은 별도이며 숫자 차이만으로 오류로 판단하지 않는다
- [ ] VISION의 운영단위·사업유형과 CORE의 사람·직원별 AI 원칙이 일치하고, 실제 수탁·담당·권한은 INDEX·READ·공식 원본에서 확인한다
- [ ] STARTER 0장(AI 필수 규칙 요약)이 현재 BM_CORE와 어긋나지 않는다
- [ ] 공유드라이브·STARTER·INDEX 접근자가 모두 STARTER 2장 인원 목록 또는 관리 계정으로 설명된다
- [ ] INDEX `담당자`가 각 READ 1장 참여(책임자)와 같다
- [ ] GitHub raw 주소로 BM_CORE·OPS·템플릿이 열린다
- [ ] 구형 운영문서가 archive·99_시스템백업에만 있고 현재 규정으로 혼동되지 않는다
- [ ] 같은 규칙이 두 파일 이상에 중복 서술되지 않았다
- [ ] 살아있는 문서가 모두 INDEX(`프로젝트`·`공통문서` 탭)에 링크돼 있다
- [ ] 같은 사실이 두 곳 이상에 값으로 적혀 있지 않다(INDEX `다음 할 일`·`접속요약`·`열린할일`은 `할일` 탭 자동 보기)
- [ ] Drive에 계속 고치는 `.md` 파일이 없고, Google 문서 이름에 `.md`가 없다
- [ ] 모든 READ·GUIDE에 0장 요약이 있고, GUIDE 안에 바뀌는 상태표가 없다
- [ ] 작업 폴더에 LEGACY·백업 파일이 없다(98·99에만)
- [ ] 진행 프로젝트의 작업 폴더에는 같은 실무문서의 `초안`·`vN`·`검토안`이 여러 개 남아 있지 않고 현재본 1개만 있다
- [ ] 프로젝트 `99_이전버전`에는 일반 작업 과거본만 있고 공식 제출·승인·계약·정산·증빙·결과물은 들어가 있지 않다
- [ ] 매번 읽는 규칙은 STARTER 0장뿐이고, CORE·OPS·부록은 필요한 장·탭·구간만 읽도록 연결돼 있다

## 2. INDEX·READ 정합성
- [ ] 정규 프로젝트 행의 Drive·READ 링크가 열린다
- [ ] INDEX `진행상태`가 READ 0장과 일치한다
- [ ] READ 3장에 할 일이 직접 적혀 있지 않다(할일 탭 링크만)
- [ ] `할일` 탭 `완료` 행을 `할일_보관`으로 옮겼다, `접속요약`·`열린할일`·`다음 할 일` 수식이 오류 없이 표시된다
- [ ] `사업발굴` 탭의 `종료`·`보류`·`프로젝트 전환` 행을 `사업발굴_보관`으로 옮겼고, 원문마다 `_요약` 문서가 있다
- [ ] 일정이 지난 프로젝트가 `진행`으로 방치되지 않았다
- [ ] `업데이트요청`에 오래된 `대기` 요청이 없다
- [ ] 신규 프로젝트에 READ·LOG·부록 3종이 같은 프로젝트 폴더에 생성돼 있다
- [ ] READ에는 핵심 상태·결론만 있고 상세 실무정보는 부록에 있으며, READ에 `부록 > 탭/제목 > 항목 참조`가 남아 있다
- [ ] AI가 부록 전체를 기본으로 읽지 않고 필요한 탭·구간만 읽는다. 큰 부록은 탭 또는 분야별 부록으로 분리돼 있다
- [ ] 진행 프로젝트마다 책임자가 지정돼 있다(미지정이면 대표)
- [ ] READ가 최신 템플릿 Schema를 따르고, 0장 요약이 있다
- [ ] READ 결정사항에 등급과 결정 주체(실명)가 있고, 각 프로젝트에 LOG가 있으며 READ 6장에 링크돼 있다
- [ ] READ 6장이 `서류 · 상태 · 링크/위치` 목록이고, 날짜 붙은 진행 기록이 쌓여 있지 않다(결정은 4장, 경위는 LOG)
- [ ] READ에 과거 값 흔적(→, 기존, 정정)이 남아 있지 않다(이전 값은 LOG에)
- [ ] 변동 가능한 정보(도구명·모델명·견적)가 근거 없이 확정 사실로 남지 않았다

## 3. 저장 절차 (실제 시나리오로 검증)
- [ ] 확정 변경이 저장 명령 없이 READ에 반영되고, 쓰기 후 재확인됐다
- [ ] 변경 없는 업무에 `READ 변경 없음`이 표시됐다
- [ ] 결과물 파일 저장과 READ 기록을 따로 확인했다
- [ ] 저장 실패 시 업무 완료와 기록 미완료를 구분하고 복구할 내용을 남겼다
