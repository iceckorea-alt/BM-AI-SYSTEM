# BM Digital 1.0 — 상위 원칙

규정 v3.3 · 2026-10-23 · BM 디지털 운영 최상위 내부 기준. AI는 평소 `BM_CORE.md`만 읽고, 원칙 해석이나 우선순위 충돌 판단이 필요할 때 이 문서를 읽는다.

## 1. 목적과 원칙
직원(사람)과 직원이 쓰는 AI 도구가 같은 기준으로 업무를 찾고, 판단하고, 실행하고, 인수인계할 수 있는 환경을 만든다. 모든 규정과 기록은 아래 네 목표에 맞아야 한다.
1. 끊김 없는 인계: 다른 사람이나 다른 AI가 같은 프로젝트를 이어받아도 정보·작업 손실이 없다.
2. 즉시 파악: 프로젝트 진행 상황을 READ 0장과 INDEX 한 행으로 바로 안다.
3. 다음 준비: 다음 할 일과 막힌 점, 대비할 것이 항상 적혀 있다.
4. 최소 토큰·빠른 처리: 매번 읽는 것은 최소로, 긴 파일은 쪼개서 필요할 때만 읽는다.

원칙
- 원본 1개 · 위치 1곳 · 링크는 여러 곳 — 사실은 한 곳에, 문서는 지도(INDEX)에, 살아있는 문서는 Google 문서로
- 판단 우선순위: 무손실 → 빠른 처리 → 최저 토큰. 셋이 충돌하면 앞의 것을 지킨다.
- 운영단위는 지속되고, 프로젝트는 `기획 → 진행 → 마감요청 → 종료`로 관리한다. 보류·취소는 예외상태다.
- 사용자가 파일 위치와 과거 맥락을 외워 AI를 안내하게 하지 않는다. AI가 먼저 찾는다.
- AI는 기존 자료를 먼저 찾고 필요한 최소한의 새 파일만 만든다.
- 공식 원본과 기억·색인·대화의 역할을 혼동하지 않는다.
- 규칙은 한 곳에만 쓰고, 매번 읽는 분량은 최소로 유지한다(경량 원칙).

## 2. 시스템별 공식 역할
| 시스템 | 공식 역할 |
|---|---|
| GitHub `BM-AI-SYSTEM` (Public) | AI 운영규정·역할·Skills·자동화·연동문서·규정 변경이력 |
| Google Shared Drive `BM` | 실무자료·최종 산출물, 실제 PROJECT_READ, 입구 `BM_STARTER` |
| Google Sheets `BM_PROJECT_INDEX` | 전체 프로젝트 중앙 목록 |
| PROJECT_READ (Drive) | 프로젝트별 현재 최종 상태·결정·다음 행동·핵심 링크 |
| PROJECT_LOG·부록 (Drive) | 변경 이력(추가만) · 참조용 상세. 평소 읽지 않음 |
| Airtable `BM_ACCESS_REGISTRY` | 계정·SNS·서비스 접속정보와 접근권한 대장 |
| Docswave | 전자결재·기안·품의·지출·인사·근태·급여·계약 |
| Canva | 디자인 제작·편집 원본 |
| Gmail (`info@` 메일 전용) | 대외 커뮤니케이션 |
| Google Calendar | 공식 일정·행사·회의·마감 |
| AI 작업공간 (Claude, ChatGPT 등) | 조사·분석·작성·실행. 채팅 기억은 공식 기억이 아니다. |

## 3. 정보 흐름
입구 `BM_STARTER` → 규정 `BM_CORE` → INDEX에서 프로젝트 위치 확인 → READ에서 현재 맥락 확인 → 필요한 원본만 확인 → 업무 수행 → 결과를 공식 원본에 반영 → 확정 변화는 READ, 위치·상태·담당·다음 할 일 변화는 INDEX에 반영 → 마감은 `ops/OPS_CLOSING.md` 절차.

## 4. 규정 우선순위
법령·계약·지원기관 강제조건 → BM Digital 1.0(이 문서) → BM_CORE → OPS 파일·템플릿 → 승인된 분야별 내부규정 → 현재 업무지시·프로젝트 맥락

## 5. 사실 확인 우선순위
공식 계약·공문·결재·증명서·최종 승인 원본 → 최신 실무 원본 → PROJECT_READ → PROJECT_INDEX

## 6. 조직·법적 경계
BM은 대외적으로 하나의 브랜드를 지향하되, BM서울과 BM인천의 법적·회계·세무·보조금·정산 책임은 실제 주체별로 구분한다. 국제문화교류센터 등 별도 법인·단체의 원본을 BM 체계에 섞지 않는다.

## 7. 보안·권한
고위험 비밀정보 저장 금지, 되돌리기 어려운 작업의 승인, 권한 우회 금지를 원칙으로 한다. 세부는 `BM_CORE` 7장과 `ops/OPS_ACCESS.md`.

## 8. 변경관리
- AI 운영규정의 공식 원본은 GitHub이며, Drive와 이중 원본으로 두지 않는다. Drive의 `BM_STARTER`는 안내판일 뿐 규정 사본이 아니다.
- READ 실제 문서는 Drive, 템플릿·작성 규칙은 GitHub. INDEX 원본은 Sheets. 접근정보 원본은 Airtable.
- 모든 규정 변경은 `CHANGELOG.md`에 기록하고, 큰 개편은 `archive/MIGRATION_YYYY-MM-DD.md`에 경위와 대응표를 남긴다. 각 문서에는 버전·기준일 한 줄만 둔다.
- 채팅에서 정한 규칙은 GitHub에 반영되기 전까지 다른 AI에게 효력이 없다.

## 9. 성공 기준
- 직원 또는 AI가 1분 안에 프로젝트와 핵심 원본을 찾는다.
- 새 세션·새 AI·새 직원이 STARTER만으로 프로젝트를 이어받는다.
- 같은 공식 문서·규칙이 여러 곳에 중복되지 않는다.
- 누가 결정하고 누가 기록했는지 READ에서 확인된다.
- 시스템이 커져도 반복 탐색·중복작업·시작 비용이 늘지 않는다.
