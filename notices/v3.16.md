# AI 공지 v3.16 — 중앙 문서관리

2026-11-15 · 대상: 모든 BM AI · 이전 공지: [v3.15](v3.15.md) · 대체됨: 없음.

## 바뀐 것
중앙 문서대장·문서 검색·발행주체별 공문 진입·견적/서식/결재 기록을 도입했다. 실무 원본은 기존 위치에 유지하고 대장들은 공통 회사문서 폴더에 모은다. 상세 원본은 `governance/ops/OPS_DOCUMENTS.md`다. 메타데이터 수집기 코드·매니페스트·설치안내는 `integrations/document-registry/`에 있다. 기존 메일수집 프로젝트는 수정하지 않았다.

## 모든 AI가 다음 접속 때 할 일
1. 최신 STARTER 0장과 이 공지를 적용한다. 문서 업무에서는 별도 지시 없이 INDEX 공통문서 → 중앙 문서대장 → 해당 원본으로 진입한다. 일반 할 일 조회에서는 문서대장 전체를 추가로 읽지 않는다. 확인: 공통문서 링크에서 대장이 실제 열리는지 확인.
2. 실행상태 1행과 필요한 문서 행을 확인한다. 생성·수정·복사·이동 결과는 파일ID로 등록·재조회한다. 문서명·위치만으로 새 ID를 만들거나 복사본의 승인을 승계하지 않는다. 쓰기 도구가 없으면 적용은 하되 넣을 행과 쓰기 실패를 보고한다. 확인: 같은 ID가 중복되지 않는지·원본 링크가 맞는지 확인.
3. 서식대장의 사용판정과 실제 원본 버전을 확인한다. 공문 결재·날인·발송은 각각 근거를 확인하고 승인과 발송을 구분한다. 확인: 승인 대상 버전 이후 수정 여부와 발송 증빙 대조. 일부 공문 이력만 보고 다음 번호를 발급하지 않는다.
4. 자기 사람·도구의 AI적용 행만 v3.16으로 갱신한다. 현재 업무 적용과 설정 저장 상태, 실행하지 못한 조치를 구분한다. 다른 AI의 적용 상태를 대신 바꾸지 않는다. 확인: 저장한 자기 행 재조회.

## 시스템관리 / 대표 설치 계정 조치
배포 시 중앙 대장·초기 확인한 서식 목록·기존 공문 원장 연결·검색은 반영했다. 수집기는 로컬 모의 검증 완료지만 **Google Apps Script 프로젝트 설치·권한 승인·최초 전체 수집·후속 예약 실행은 미완료**다. 연결 도구에는 프로젝트 생성/실행 기능이 없고 PC 브라우저 창 활성화도 실패하여 구글 설치를 수행하지 못했다. 실제 상태는 비공개 대장의 실행상태·설치안내·INDEX 업데이트요청에서 확인한다.

대표 계정 한 명이 중앙 대장 → 확장 프로그램 → Apps Script에 Code.gs와 매니페스트를 설치하고 BM_install을 실행·승인한다. 최초 전체 순회, BM_sync 15분 트리거 1개, 다음 예약 실행 성공을 각각 확인한 뒤만 운영 상태를 갱신한다. Google 승인 화면은 사람이 처리한다. 이미 설치된 경우 먼저 실제 프로젝트·예약 실행을 확인하여 중복 설치하지 않는다.

모의 검증 범위: ID 갱신·재시도·이름/경로 변경·수동 필드 보존·복사본 확정 미승계·중복 거부·수식 텍스트 처리·문서 선별·제외 폴더·부모 경로·접근 오류·쓰기 실패 시 체크포인트 유지. Google 계정 권한·실제 할당량·예약 실행은 미검증. 새 AI 진입 경로는 공식 원본을 따라가는 방식으로 확인하며 독립된 새 AI 실행 검증과 구분한다.

## 하지 말 것
미설치를 자동 운영 중으로 보고하지 않는다. 승인·완료·발송·현재본을 추정하지 않는다. 원본·공문 번호·사업발굴 폴더를 임의 변경하지 않는다. 과거 기입 문서를 빈 표준서식으로 사용하지 않는다. 도장·본문·계정정보를 수집하지 않는다. 개인 AI 링크를 유일한 진입으로 사용하지 않는다.

## 앞으로의 공지
문서·메일·대장·자동화·연동·진입 경로 등 **시스템 운영 변경은 항상 해당 버전 AI 공지에 실행 조치·확인 방법·가동 상태·남은 조치를 기록한다.** 모든 AI는 다음 STARTER 진입 때 자기 권한 범위에서 실행한다. 공지가 미접속 AI의 백그라운드 실행이나 권한 부여를 뜻하지 않는다.
