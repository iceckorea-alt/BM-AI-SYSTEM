# OPS_DISCOVERY — 사업발굴 원장과 조사

규정 v3.19 · 2026-11-25. 비공개 위치·파일ID는 STARTER 및 BM_PROJECT_INDEX 공통문서에서 확인한다.

## 1. 단일 원장
사업 기회는 독립 BM_DISCOVERY_INDEX 연도별 원장에만 입력한다. 기존 INDEX 사업발굴·사업발굴_보관은 삭제하지 않고 전환 안내·보존용으로 유지한다. 프로젝트 목록·실행 할일은 기존 INDEX를 유지한다. 기회별 READ·중복 목록을 만들지 않는다.
최초 등록연도로 관리하고 종료·보류도 같은 행을 보존한다. 분기집계는 등록일 기준 자동 계산, 검토대상·마감임박은 자동 보기다. 마감 미확인은 별도 확인하며 0건을 전수검증으로 해석하지 않는다.
원문·요약은 기존 사업발굴 폴더의 YYYY 아래 둔다. 유형별 하위폴더를 만들지 않고 기존 자료 ID·링크는 유지한다. GUIDE는 기존 AI업무지침의 사업발굴 분야에서 선택해 읽는다.

## 2. 등록·중복검사
D-YYYY-NNNN 고정ID를 연도별 미사용 번호로 직렬 확정한다. 구원장·전체 연도 원장·등록대기·기존 프로젝트의 동일/유사 사업을 대조한 뒤 등록·재조회한다. 사용한 ID는 재사용하지 않는다.
중복키는 공식 도메인+공고 고유번호, 없으면 기관+공고번호+연도다. 메뉴·추적변수·페이지 차이는 같은 공고다. 같은 키는 기존 행 갱신, 별도 번호 재공고는 연결발굴ID로 원공고를 연결한다. 기관/제목 유사성·약칭·연도표현도 확인한다.
ID/키 검증과 중복경고는 보조수단이며 API·동시편집 잠금은 아니다. 직렬 등록과 쓰기 직전/후 재조회가 필수다. 연도 또는 행 수용량을 확장할 때 전체 연도 조회·집계·경고·검증 범위를 함께 확장·시험한다.

## 3. 근거와 결정
공식 원문·공고번호·접수마감·예산 단위/기간·참여자격 근거를 기록한다. 공고 게재 종료일과 접수마감을 혼동하지 않는다. 최초 원문 읽기 뒤 2,000자 이내 _요약 Google Docs에 BM 관련 과제·예산·시기·부서·근거 쪽수·미확인을 남긴다. 변경·자격 판단·신청 전에는 최신 원문을 재확인한다.
서울/인천 신청주체별로 법인/단체·소재지·실적·인력·재정·시설·공동수급을 검증한다. 공식 요건과 BM 증빙이 없으면 자격 가능으로 단정하지 않는다. 사실·AI 판단 [제안]·대표결정/일자/근거를 분리한다.
참여 승인 후에만 OPS_PROJECT 중복검사·프로젝트 생성 절차를 따른다. 발굴ID 유지, 프로젝트ID·전환일·READ 링크 기록, 상태 프로젝트 전환, READ 6장에 원문·요약/발굴ID 연결. 계산 경고는 실제 승인·프로젝트 존재를 증명하지 않는다.

## 4. 조사와 자동화
조사대상에는 공식 게시판·분야·주기·확인상태, 조사기록에는 실제 확인범위·실패·신규수·발굴ID를 남긴다. 검색·게시판·첨부 확인과 미확인을 구분한다. 공식 출처를 열지 못하면 실패로 기록한다.
기존 주간조사 참조·활성상태·다음실행·쓰기연동을 각각 확인한다. 과거 보고가 있어도 현재 예약 가동을 추정하지 않는다. 기존 자동조사 중복 생성·중단, 권한 변경, 결제는 이번 구축 범위가 아니다. 기존 조사범위의 행정구역 변경과 기관수 차이는 조사대상에서 갱신한다.

## 5. 전환·복구·가동 상태
기존 원장 백업→데이터/원문 대조→신규 원장 검증→공식 안내 전환 순서. 삭제 없이 구원장에 현행 링크를 둔다. STARTER·CORE·관련 OPS·기존 INDEX·버전 공지는 같은 현행 위치를 안내한다.
시트 집계/보기와 기존 예약의 신규 원장 자동등록은 구분한다. 설치하지 않은 잠금·예약·외부연동을 가동 완료라 기록하지 않는다. 화면 확인이 제한되면 기능 검증과 구분한다. 실제 건수·시험·미완료는 비공개 운영안내/조사기록에 남긴다.
복구는 신규 입력 이력 보존 후 백업과 차이를 대조해 대표 결정으로 안내를 되돌린다. 전체 백업을 덮어써 다른 업무 변경을 잃지 않는다.
