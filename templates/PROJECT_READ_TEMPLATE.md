# PROJECT_READ_TEMPLATE

READ Schema v2.1 · 2026-10-21 · READ·LOG를 새로 만들거나 구조를 바꿀 때만 읽는다. 실제 문서는 각 Drive 프로젝트 폴더의 Google Docs `YYYY_프로젝트명_READ`와 `YYYY_프로젝트명_LOG`.

## 작성 규칙
- 아래 `---` 사이가 각 문서 본문이다. 이 작성 규칙은 문서에 복사하지 않는다.
- **READ는 지금 유효한 최종 상태만** 담는다. 바뀐 값의 이전 내용, 경위, 정정 흔적(→, 기존, 정정)은 READ에 남기지 않고 LOG에 한 줄로 남긴다.
- **LOG는 추가만** 한다. 문서 끝에 덧붙이며 평소 읽지 않는다. 형식: `YYYY-MM-DD · 실명(도구) · 항목: 이전값 → 새값 · 이유/근거`. 새로 생긴 항목·완료는 `항목: 내용 (신규/완료)`.
- 작성자·결정 주체·담당은 실명. AI가 대신 적으면 `홍길동 (Claude 기록)`처럼 도구 표시. (`BM_CORE` 4장)
- 0장은 항상 최신으로 유지한다. 같은 사실은 READ 안에서 한 곳에만 쓴다(결정 4장, 운영 정보 2장). 할 일은 READ에 쓰지 않고 INDEX `할일` 탭에만 쓴다(v3.4).
- 해당 없는 섹션·항목은 만들지 않는다. 빈 `미연결` 줄을 나열하지 않고 6장 끝 `미연결:` 한 줄에 모은다.
- 확인되지 않은 값은 `미확정`. 추정하지 않는다.
- 3장은 `할일` 탭 링크 한 줄만 둔다. 상태 값은 `진행`·`할 일`·`대기`·`승인 필요`·`완료`. 완료는 탭에서 `완료`로 바꾸고 LOG에 남긴다.
- 4장은 지금 유효한 결정만 최신순. 등급 `[대표결정]` `[책임자결정]` `[제안]`과 결정 주체(실명). 뒤집힌 결정은 4장에서 새 결정으로 바꾸고 이전 결정은 LOG로. v2.0 전환 때 결정 주체가 기록되지 않은 과거 결정은 `[이관]`, 대표가 확인하면 `[대표결정]`으로 바꾼다.
- 긴 파일은 쪼갠다: 프로젝트 고유 상세(곡목록·코드표·장비표·명단 등 참조용)는 READ에 넣지 않고 같은 폴더 `YYYY_프로젝트명_부록` 문서로 두고 6장에 링크한다. READ 본문은 약 6,000자 이내를 목표로 한다.
- 대외 프로젝트는 `마감요청` 전 실제 결과보고서 파일 링크를 6장에 연결한다(`ops/OPS_CLOSING.md`). 당초 계획 대비 변경사항은 LOG에서 뽑는다.

# YYYY_프로젝트명_READ
READ Schema v2.1

## 0. 요약 — YYYY-MM-DD 실명(도구)
- 상태: 기획/진행/보류/마감요청/취소/종료 — 현재 단계 한 줄
- 핵심 일정: 다음 주요 일정·행사일·마감
- 다음 할 일: INDEX 할일 탭 기준 (우선 3개는 접속요약 탭에 자동 표시)
- 최근 결정: 한 줄
- 막힘·미확정: 한 줄

## 1. 기본정보
- 프로젝트 ID · 주관 조직(운영단위)
- 대외명·브랜드:
- 발주·지원기관:
- 기간·장소:
- 사업비:
- 계약·회계 주체·구조:
- 참여: 책임자 실명 / 참여자 실명

## 2. 실행 정보
프로그램·장소·현장조건·대상·목표 등 지금 유효한 운영 정보.
- 주의: 이 프로젝트에만 적용되는 확정된 주의사항 (전사 규칙은 반복하지 않음)

## 3. 할 일
- 할 일 원본: BM_PROJECT_INDEX 할일 탭(이 프로젝트 ID, 완료분은 할일_보관). 이 장에는 할 일을 적지 않는다 — INDEX 링크

## 4. 결정사항 (지금 유효한 것, 최신순)
- MM-DD [대표결정] 결정 내용 (결정 실명)

## 5. 이슈·외부 의존
- 이슈·리스크 또는 기관·업체 의존 — 영향 · 대응 · 상태(열림/대응중/해소)

## 6. 핵심 링크
- 변경 로그(LOG, 평소 읽지 않음): 링크
- 상세 부록(있을 때만, 평소 읽지 않음): 링크
- 프로젝트 폴더 / 사업계획 / 계약·협약 / 실행계획 / 홍보 / 결과보고
- 공문·Docswave / Canva / Calendar (있을 때만)
- 연락: 대외 담당자(소속·연락처)
- 미연결: 항목 나열
