# 비엠업무 (BM 업무 진입 스킬)

스킬 v3.0 · 2026-10-21 · 이 스킬은 '어디서부터 읽는가'만 안내한다. 규칙 원본은 GitHub `governance/BM_CORE.md`이며, 이 스킬과 다르면 원본을 따른다.

## 시작
1. Google Drive 연결 도구로 공유드라이브 `BM` 루트의 `BM_STARTER`를 읽는다(제목이 .md여도 Google Docs). 개인 Drive·백업·LEGACY 파일을 대신 읽지 않는다.
2. STARTER가 안내하는 raw 주소로 `governance/BM_CORE.md`를 읽는다. github.com 페이지가 아니라 raw 주소를 쓴다.
3. INDEX `프로젝트` 탭만 읽어 진행 프로젝트를 파악한다. 접속 단계에서 각 READ를 열지 않는다.
4. 사용자가 프로젝트를 지정하면 그 READ의 0장 요약부터 읽고, 필요할 때만 아래 섹션·원본을 연다.
5. 업무 종류에 맞는 OPS 파일만 추가로 읽는다(BM_CORE 9장). 같은 채팅에서 이미 읽은 규정은 다시 읽지 않는다.
6. 읽지 못한 것은 '못 읽음'으로 보고하고 추정하지 않는다.

## 시작 보고 (짧게)
- 읽기 성공·실패: STARTER / CORE / INDEX (/ READ)
- 진행 프로젝트: `ID | 이름 | 상태 | 다음 할 일` (종료·취소 제외, INDEX `다음 할 일` 열 사용)
- 책임자 미지정, 일정이 지났는데 `진행`인 행이 있으면 한 줄 경고
- 마지막에 `오늘 뭐부터 할까요?`
사용자가 처음부터 특정 업무를 지시했으면 목록을 생략하고 바로 그 프로젝트로 들어간다.

## 작업 중
- 작성자 코드: 지시자 코드 + `·CL`(Claude) / `·GPT`(ChatGPT). 지시자를 모르면 묻는다.
- 확정 변경은 명령 없이 READ에 저장: 최신본 다시 읽기 → 바뀐 줄만 수정 → 다시 읽어 확인. 0장 상태·다음 할 일이 바뀌면 INDEX 같은 행도 맞춘다(권한 범위 밖이면 업데이트요청).
- 완료보고에 `READ 저장·확인 완료 / READ 변경 없음 / READ 저장 미완료 — 사유` 중 하나를 표시한다.
- `매뉴얼`·`도움말` 등 → `guides/BM_AI_USER_QUICK_GUIDE.md`. `마감` → `governance/ops/OPS_CLOSING.md`.

## 한계
기존 연결 도구를 호출하는 지침형 스킬이다. 백그라운드 실행·결재 자동 감지는 없다. 연결되지 않은 시스템(Docswave 등)은 연결된 것처럼 말하지 않는다. 설치된 스킬 사본이 이 원본과 다르면 원본을 따른다.
